# V1.0.1 UI Audit

Factual audit of the existing interface, captured before Task 01 token work
(layer was introduced in the same task; component styling was not rewritten).

## Current UI strengths

- Single cohesive dark stylesheet with a clear `:root` variable set already
  in place (V1.0) — colors, one accent, one radius, two font stacks.
- Subtle border-led design: only 8 `box-shadow` uses across 1386 lines
  (mostly overlays/drawers, not decorative elevation).
- Focus states exist on interactive controls: 11 `:focus-visible` rules,
  accent-colored ring.
- Solid accessibility floor in markup: 21 `aria-*`/`role` attributes in the
  blade shell (toolrail `aria-label`, `aria-live` busy status, labelled
  panels/footers).
- Clear layout regions: `header.topbar` → `nav.toolrail` (8 tools) →
  workspace (`#empty-state`, `#busy`, canvas) → `aside#panel` →
  `footer.appfoot`.
- Control styling is consistent: `.btn` family (primary/secondary/ghost
  sizes), `.tool` rail buttons, `.adjust__range` sliders with shared thumb
  styling.
- Feature UI (history bar, project controls, export panel, drawer, modal,
  toast/busy) already follows the shared classes — good reuse candidates.

## Current UI problems

- One monolithic `editor.css` (1386 lines, ~26.5 kB) mixing tokens, layout,
  components and feature styles with only comment separators.
- Token layer was thin: no spacing scale, no radius scale (single
  `--radius: 6px`), no control-height, no typography size scale, no
  success/warning tokens, no surface/overlay distinction beyond 5 bg values.
- Scattered hardcoded values (post-token-change residuals): `#3a3a44`
  control borders (lines 131/684), `#dcdce2` slider thumbs (616/641),
  `#ffffff`/`#0b0b0d` near the modal (1020/1028) — candidates to fold into
  tokens later.
- V1.0 accent was gold (`#d9b06c`) with a stray hover hex (`#e6bd7b`) and a
  stray rgba tint outside the token block — the exact "scatter" risk V1.0.1
  removes.
- `EditorUI.js` is a 47.6 KB monolith rendering all tool panels as HTML
  strings — fine to ship, but later redesign tasks will want it split or at
  least sectioned.
- Version/identity strings live in three places (blade title/footer,
  `ProjectSerializer.APP_VERSION`) plus tests — must move together in the
  final V1.0.1 release task.
- Responsive behavior is minimal (3 media queries: 1100/900/640) and
  intentionally deferred — no tablet/mobile editing experience.

## Components that can be reused

- `.btn` / `.btn--primary` / ghost & icon variants (already token-driven via
  `--accent`, `--color-on-accent`).
- `.tool` rail buttons with `is-active` + inset indicator (non-color signal
  already present).
- `.adjust__range` slider styling (shared track/thumb).
- `.panel`, `.topbar`, `.toolrail`, `.appfoot` layout shells.
- `.modal` overlay + `.drawer` (shadow used only where it belongs).
- `#busy` overlay (role=status, aria-live) and `#empty-state` guidance.
- History bar (`.topbar__hist-*`), presets row, export panel markup.

## Components that should be redesigned later

- Editor header/topbar composition (full V1.0.1 redesign task).
- Tool panel internals (section titles, control rows, spacing rhythm).
- History panel/labels, project controls cluster, export modal layout.
- Modal/drawer visual language (scrim, radius, padding) once the full
  component pass lands.
- Empty-state artwork/typography.
- Anything mobile/tablet — explicitly V1.0.2 Beta.

## CSS/style files involved

- `resources/css/editor.css` — the whole editor (entry).
- `resources/css/tokens.css` — V1.0.1 token layer (new, Task 01), imported
  by `editor.css`.
- `resources/css/app.css` — Tailwind entry for the default Laravel welcome
  route only; not used by the editor shell.
- `public/build/assets/*` — built output (Vite).

## JavaScript/UI files involved

- `resources/js/editor/ui/EditorUI.js` — panel HTML rendering, all feature
  panels.
- `resources/js/editor/ui/UploadController.js`, `ZoomController.js`,
  `busy.js` — workspace/UI helpers.
- `resources/js/app.js` — bootstrap, wires history/project/export/text/mask
  controllers.
- Controllers rendering UI text/states: `TextController`, `MaskController`,
  `ProjectController`, `HistoryManager`, exporter.
- `resources/views/editor.blade.php` — shell markup (topbar, toolrail,
  workspace, panel, footer).

## Potential regression risks

- Computed-style tests: step8 (focus-visible outline, theme-color,
  `.empty__privacy` font size), step11 (`:focus-visible` rule count ≥ 3) —
  token changes must not remove/alter those rules.
- Exact identity tests: title/footer/version strings asserted exactly by
  step7/8/12/13/14, run_tests, manual14 — deferred to the final V1.0.1 task.
- Layout probes measure button padding/margins — avoid changing control
  dimensions in design-system-only tasks.
- Accent-colored computed styles (active tool, focus ring, primary button)
  change appearance gold → Neo Yellow by design; no test asserts the old
  gold value (verified: no `#d9b06c` references in any suite).
- Editing engine (pipeline/mask/grade/export/history/serializer) is
  presentation-untouched — protected by design (Task 01 changes are CSS +
  docs + test-stability only).
