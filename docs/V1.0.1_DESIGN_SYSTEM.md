# V1.0.1 Design System — Neo Yellow

Source of truth: `resources/css/tokens.css` (single token layer, imported by
`editor.css`). This document explains the roles and rules; the values live in
one file only.

## Neo Yellow tokens

One controlled family — no random yellows anywhere else (enforced by
`task01_tests.mjs`).

| Token | Value | Role |
|---|---|---|
| `--color-accent` | `#e8ff00` | Primary interactive accent: primary buttons, active tools, selection, sliders, indicators |
| `--color-accent-hover` | `#f1ff4d` | Brighter hover state |
| `--color-accent-active` | `#d5eb00` | Pressed/selected state |
| `--color-accent-subtle` | `rgba(232,255,0,0.16)` | Low-opacity highlight (replaces legacy `--accent-soft`) |
| `--color-accent-wash` | `rgba(232,255,0,0.05)` | Near-invisible tint |
| `--color-accent-text` | `#e8ff00` | Accent-colored text — only where contrast is safe (dark backgrounds) |
| `--color-on-accent` | `#17130a` | Content on yellow fills (dark text, ≥ 4.5:1 on accent) |
| `--color-focus` | `= --color-accent` | Keyboard focus ring |

Accent discipline: **accent and interaction language, not a theme.** Yellow
appears on primary actions, active tools, selection states, important
indicators, focus and key controls — never as large fills, panel
backgrounds, body text or decoration. `task01_tests.mjs` asserts no
accent-filled region larger than 50 000 px² in the default view.

## Background / surface tokens

Deep near-black scale, no pure black:

| Token | Value | Role |
|---|---|---|
| `--color-bg` | `#0b0b0d` | Application background (also `<meta theme-color>`) |
| `--color-surface` | `#101013` | Panels |
| `--color-surface-raised` | `#17171b` | Raised panels, controls |
| `--color-surface-hover` | `#1d1d22` | Hover fill |
| `--color-workspace` | `#08080a` | Canvas area — visually separated from UI panels |

Borders over shadows (subtle `--color-border: #212127`,
`--color-border-strong: #2c2c34`; shadows reserved for overlays/drawers).

## Typography tokens

Existing system kept — **no new font dependency**:

- `--font-ui` (system sans stack), `--font-mono` (mono stack).
- Scale: `--text-xs: 11px`, `--text-sm: 12px`, `--text-md: 13px` (base UI),
  `--text-lg: 15px`, `--text-title: 18px`.
- Hierarchy to apply in later tasks: application title → section title →
  tool title → control label → value → helper text → status text.

## Spacing / radius / control sizing

- Space scale: `--space-1…--space-8` = 4/8/12/16/20/24/32 px.
- Radius scale: `--radius-sm: 6px` (controls), `--radius-md: 10px`,
  `--radius-lg: 14px` (panels/modals).
- `--control-height: 34px` — matches the existing `.btn`; applied
  gradually in later redesign tasks (layout probes measure current sizes).

## Status tokens

`--color-danger: #ff4d5a`, `--color-success: #4ade80`,
`--color-warning: #facc15` — always paired with text/icon, never color-only.

## Legacy compatibility

All V1.0 variable names remain valid, aliased onto semantic tokens in
`tokens.css` (`--bg-app`, `--bg-panel`, `--bg-raised`, `--bg-hover`,
`--bg-workspace`, `--line`, `--line-strong`, `--text`, `--text-dim`,
`--text-faint`, `--accent`, `--accent-soft`, `--danger`, `--radius`,
`--font`, `--mono`). Existing `var()` references need no edits; component
rules are untouched (Task 01 is not a redesign).

## Design language principles (V1.0.1)

- **Backgrounds**: deep near-black, never pure black everywhere; canvas area
  reads as a distinct surface from panels.
- **Surfaces**: subtle steps between app background, panel, raised panel,
  control and overlay.
- **Borders**: prefer subtle borders; shadows only for overlays/drawers.
- **Typography**: clear hierarchy, existing fonts only.
- **Buttons**: primary (yellow fill + dark text), secondary, ghost, danger,
  icon, plus active/disabled states — defined by tokens, restyled in later
  tasks.
- **Controls**: consistent height/radius/spacing/focus/disabled via the
  token scale.

## Accessibility principles

- Visible focus: accent focus ring (`--color-focus`), 11 existing
  `:focus-visible` rules kept; verified live by keyboard Tab.
- Contrast: text ≥ 4.5:1 on its background; dark content on yellow fills
  (`--color-on-accent`); accent text only on dark surfaces (both ratios
  computed in `task01_tests.mjs`).
- No color-only communication: active tool = `is-active` class + inset
  indicator + accessible name; status colors carry text/icons.
- Sliders, tool states, disabled states keep their labels/ARIA; keyboard
  operation unchanged.
- Nothing in the token layer lowers an existing a11y guarantee — protected
  by step8/step11/step14 suites.
