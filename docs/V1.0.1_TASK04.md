# V1.0.1 — Task 04: Complete UX & Editing Workflow Redesign

Status: complete · Suite: `task04_tests.mjs` 70/70 · Manual: `task04_manual.mjs` 42/42 · Regression: 2554 passed, 0 failed

## Objective

Fix every piece of friction found in the Task 03 UX audit (`docs/V1.0.1_UI_AUDIT.md` + `task04_audit.mjs`): keyboard-dead crop workflow, silent state loss (crop draft, autosave window, focus), unclear reset scope, color-only errors, missing success signals, panel switch feedback, and focus dropped on `<body>` after list re-renders — without touching the engine layer, adding features, or changing the design language.

## UX audit findings → resolutions

| # | Finding (audit evidence) | Resolution |
|---|---|---|
| 1 | Crop box keyboard-dead: focus stayed on the tool button; `aria-label` promised "arrow keys move, Enter applies" but `onKeyDown` had no Enter branch and the box was never focused | `CropController.setActive(true)` now focuses the box (`preventScroll`); Enter applies (task04 tests, manual W5) |
| 2 | Escape on the box also unreachable (same focus gap) | Fixed by the same activation focus; Escape→cancel verified live |
| 3 | Leaving crop with a modified draft destroyed the overlay silently ("status after abandoning crop: unchanged") | Deactivate reports `Crop discarded — nothing was applied.` only when `draft ≠ full-frame`; apply/cancel reset the draft first so no false messages |
| 4 | Reload within the 800 ms autosave debounce lost the session | `pagehide` flush: pending timer cleared + `saveSession(historyState(state.get()))` fires as the page goes away |
| 5 | Start Fresh could be resurrected by an already-scheduled autosave write | One module-scope `autosaveTimer`, cancelled at the **end** of `startFresh()` — including the write its own `setStatus` re-schedules (found while testing: the status update re-enters the subscriber) |
| 6 | Export button disabled during export blurred focus to `<body>`, never restored | `sync` tracks `lastExporting`; on completion, focus returns to `#btn-do-export` only if `activeElement === document.body` |
| 7 | Reset said "every adjustment" but also clears crop, text, mask, grade, composition | Status now: `Reset — every edit is back to its default; your photo stays open.` + explanatory `title` on `#btn-reset` (still contains "Reset", never contains lowercase "text") |
| 8 | Errors were color-only (`is-error` = red) | `::before` glyph `⚠ ` on both `.statusbar__status.is-error` and `.export__status.is-error` — generated content, `textContent` untouched |
| 9 | No success signal anywhere (save/export completion looked identical to idle) | `status.type === 'success'` → `.is-success` (`--color-success`) on statusbar + export line; set by export completion and project save |
| 10 | Custom-look rename/delete re-render (`replaceChildren`) dropped focus on `<body>` | `refocusCustomPresets()` refocuses the first delete button (or the name field) — only when focus actually landed on `body`, so blur-to-another-control is never hijacked |
| 11 | Add Text left focus on the button; typing required an extra click | After `state.addText()`, focus + `select()` on the content textarea (default text replaced by first keystroke) |
| 12 | Tool switches were instant with no transition; panel scroll position lost | `.panel--enter` (140 ms opacity + 6 px translate, restarted only on a real tool switch — mask rebuilds excluded); per-tool `scrollTop` memo round-trips |
| 13 | (verified OK, unchanged) empty state, dragover, slider immediacy, preset marking, undo/redo labels, busy pill, font-menu Escape, tab chain, recovery banner flow | Covered by regression + manual workflows as living contracts |

## Workflow improvements

- **Crop is keyboard-first now**: Enter crop → box focused → arrows move → Enter applies → Escape cancels → leaving with pending work says so.
- **Nothing dies silently**: crop discard, autosave flush on close, start-fresh really starts fresh (proven: session stays `null` past the debounce window).
- **Every outcome is announced**: errors red + ⚠, completions green, reset explains scope, undo/redo echo `Undo:`/`Redo:` labels (existing, re-verified).
- **Focus survives transitions**: tool switch (never `<body>`), export busy window, custom-look re-render, Add Text → caret in field.
- **Panels respond**: 140 ms entrance on real switches only; scroll position kept per tool; reduced-motion users get none of it.

## Accessibility improvements

- Errors are never color-alone (`⚠` generated content on both status surfaces; `role="status"` `aria-live="polite"` re-verified).
- Keyboard flow of the crop box is now actually reachable (focus lands on activation; label promises kept).
- Focus visibility: `:focus-visible` ring on sliders re-shot (`15-keyboard-focus.png`, `1px solid` accent).
- Reset button gained a descriptive `title`; success/error states carry class + color + glyph (not color-only).
- `prefers-reduced-motion: reduce` disables the panel entrance (live-checked: `animationName === 'none'`).

## Project workflow

- **Save**: `Project saved — editing instructions only, no image.` + `.is-success`.
- **Import errors**: invalid file → `…nothing was changed.` red + ⚠, state untouched (step13 contract intact).
- **Missing image**: project opened before a photo → `Project settings loaded — open an image to restore them.` (covered by step13).
- **Recovery**: debounce 800 ms unchanged; `pagehide` flush closes the reload-window hole; banner → Restore / Start fresh verified end-to-end incl. "start fresh really starts fresh" (no banner on next visit, storage empty).

## Export workflow

- Format/quality/output persistence across switches unchanged (step9/export suites).
- Completion: message + `.is-success` on statusbar **and** export line; button re-enabled, re-focused if nothing else claimed focus; label back to `Export`.
- Failure paths unchanged and covered by `export_tests` (encode failure → `Couldn't create…`, alloc failure → `Unable to export…`, both `is-error` + ⚠ glyph via CSS).

## Error handling

- Invalid upload: `is-error` + ⚠ glyph, `textContent` stays glyph-free (tested).
- Invalid project: safe message + `is-error` + glyph on both surfaces.
- Export failures: pre-existing messages now also get the non-color glyph automatically (same CSS rule).
- All error types still suppress `is-success` and vice versa (checked).

## Performance

- CSS total **59.03 kB** (58.61 → +0.42: keyframes, success/error rules); JS **97.00 kB** (96.12 → +0.88). Within the ~60 kB CSS budget; `task04_tests` enforces ≤ 61440 B.
- One forced reflow (`panel.offsetWidth`) per *tool switch* only — not per state change; `perf_tests` 29/29 green.
- Scroll memo is a 5-entry `Map`; pagehide flush is a single synchronous `saveSession`.

## Privacy / security

- No new network requests, dependencies, fonts, or storage keys. `pagehide` writes only to the existing `8pattern.session` localStorage entry (state only, never pixels — same contract as the debounce).
- `⚠` is a literal character in CSS; no external assets. Reset `title` is static text.

## Known limitations

1. `.panel--enter` shifts layout ≤6 px mid-animation; all geometry checks pass (run at ≥220 ms after switches), but a screenshot taken within 140 ms of a switch captures the transition.
2. Export status reserves one line (`min-height: 16px` — locked contract); a wrapped 2-line error pushes the PROJECT section down ~17 px. Raising the reserve would break the `task03`/`step9` `minHeight === '16px'` assertions, so it stays.
3. Scroll retention covers the panel body only; the history list's internal scroll (tab-focus auto-scroll) is not memoized.
4. `startFresh` cannot be reached from the UI with an image loaded (banner-only button); the cancellation covers the programmatic path and the banner path alike — tested via `window.__project.startFresh()`.
5. No modal/dialog exists in V1.0, so modal-specific keyboard rules from the brief were N/A.
6. A file-meta "dirty" dot was considered and skipped: the history list already communicates edits, and saved-vs-unsaved has no reliable semantics for a downloaded project file (§33 explicitly allows not inventing a system).
